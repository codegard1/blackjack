# Cloud Sync

* Player profiles and their lifetime statistics, and the game in progress, are saved to a MongoDB Atlas database through Netlify Functions, so they outlive the browser's storage and a game resumes where it was left off. The browser copy stays as a cache: the game works unchanged offline or when the database is unreachable, and the next change is sent once the connection is back.
* Each anonymous browser asks the server for an owner id once (`POST /api/owner`) and keeps it in local storage; the server stores that browser's profiles and game under it. The id is signed with a secret only the server holds (`browser:<uuid>.<signature>`), so a client cannot invent ids. When `VITE_GOOGLE_CLIENT_ID` is configured, the Players dialog also offers Sign in with Google: `POST /api/owner` verifies the Google ID token against Google's public keys and issues a deterministic signed `google:<sub>.<signature>` owner id, so signing in with the same Google account on any browser shares the same profiles, lifetime statistics, and game in progress (merging any anonymous hands played before signing in). Documents not written for 90 days expire on their own.
* The functions live in `netlify/functions`: `/api/profiles` reads (GET) and replaces (PUT) one owner's profiles, `/api/game` does the same for the game in progress (sending the newest 200 activity log entries), `/api/owner` issues anonymous browser owner ids and exchanges Google ID tokens for signed Google owner ids, and `/api/health` reports whether the database answers. The owner id is sent in the `Authorization` header (`Bearer <ownerId>`), so it stays out of request logs. All are rate limited by IP address, bodies are capped (16 KB for profiles, 64 KB for a game), and only the fields the game defines are stored. The shared client in `netlify/lib/mongo.ts` is created once per function instance and reused, as MongoDB recommends for serverless functions.
* Credentials are never in the repository. The functions read `MONGODB_URI` (the Atlas connection string, marked as a secret), `MONGODB_DB`, `OWNER_ID_SECRET` (a random string of 32 or more characters that signs owner ids, also marked as a secret), and optionally `VITE_GOOGLE_CLIENT_ID` (an OAuth 2.0 Web Client ID from Google Cloud Console with `http://localhost:3000` and the production origin in Authorized JavaScript origins) from environment variables set in the Netlify UI under Site configuration, Environment variables. For local development copy `.env.example` to `.env` (ignored by git) and fill in the values; `npm start` loads them, and `@netlify/vite-plugin` runs the functions inside the Vite dev server at `http://localhost:3000/api/...`.
* Atlas setup: a database user with the `readWrite` role on the `blackjack` database only, and a Network Access entry for `0.0.0.0/0`, because Netlify functions have no fixed outbound addresses. The first writes create the `profiles` and `games` collections.
